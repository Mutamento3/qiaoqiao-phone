### Bug 1: APK 元数据版本永远 1.10.216 (长期)
- **症状**: 用户从 GitHub release 下 v1.10.230/v1.10.231 native APK, 安装包详情显示 versionName "1.10.216", 已安装也是 1.10.216.
- **根因**: `android-native/app/build.gradle.kts` 第 16-17 行**硬编码** `versionCode = 216` / `versionName = "1.10.216"`, 从来没动过. CI 只用 src/version.json 命名 release tag/产物, 不动 build.gradle.kts.
- **后果**: 整个 1.10.217~231 系列的 native APK 内部 versionName 都是 "1.10.216", 用户装的"新版本"在系统里看不到, 没法判断升级.
- **修复 (v1.10.232)**:
  1. build.gradle.kts 占位符改 `versionCode = 0` / `versionName = "0.0.0"`
  2. `build-native-apk.yml` 加 "Sync version" 步骤, sed 把 src/version.json 注入:
     - versionName = src/version.json 的 version 字段 (e.g. "1.10.232")
     - versionCode = versionName 去点号 (e.g. 110232)
  3. 后续 src/version.json 改一处即可, APK 元数据自动同步.

### Bug 2: 装上一直转圈进不去 (v1.10.230)
- **症状**: v1.10.230 native APK (49MB) 装上后 splash "加载中..." 永远不消失, Vue 不挂载.
- **诊断难点**: 没有 logcat, 用户看不到具体卡哪. Toast "PWA 加载中..." 在 5s 后才弹, 也不说明错因.
- **可能根因** (待 v1.10.232 装上后看诊断):
  - R8 minify 删了 assets 资源 (isMinifyEnabled=true + isShrinkResources=true)
  - 某个 chunk JS 在 Android 14 WebView 首次加载失败
  - Service Worker / PWA manifest 注册冲突
  - 字体加载失败导致 splash 移除脚本卡住 (但 splash 是 OOTB HTML, 不依赖 JS)
- **修复 (v1.10.232)**: MainActivity + AppPrefs 加详细诊断
  - onCreate 时读 SharedPreferences 上次 diag/err, 有就 Toast
  - onReceivedError → 写 lastLoadError
  - onReceivedHttpError → 计数
  - onPageFinished 后 evaluateJavascript 检查 #app 子元素 / readyState / splash opacity → 写 lastLoadDiag
  - 30 秒硬超时 → 写 lastLoadDiag 含 TIMEOUT 标记
  - 启动时清掉上次状态 (避免每次启动都弹)
  - 这样下个版本用户装上, 转圈后下次启动会看到 Toast "上次加载出错: xxx" 或 "Vue 未挂载: {readyState:..., appChildren:0,...}"

## v1.10.233 (commit 092c878) - 永久转圈真根因: 路径多层映射
- **真根因定位**: 232 的诊断方向误判 (当时怀疑 R8/minify/SW). 实际是 WebViewAssetLoader 路径 bug:
  - Vite `base: './'` 生成 `<script src="./assets/main.js">` 等相对引用
  - index.html 在 APK 的 `assets/index.html`, 浏览器把 `./assets/main.js` 解析成
    `https://appassets.androidplatform.net/assets/assets/main.js` (**多一层!**)
  - WebViewAssetLoader 把 `/assets/` 映射到 `assets/`, 去找 `assets/assets/main.js` → **404**
  - JS/CSS 全 404 → Vue 永不挂载 → splash `#native-splash` 永远转圈
  - main.js 内部 import 的 chunk 也是 `./assets/...`, 同样 404 (**只修入口救不了**)
- **这是所有 native 包白屏的真根因** (不止 230/232), 之前一直没人真在手机装出来过 / 没反馈
- **修复**: MainActivity 自定义 `/assets/` path handler, path 以 "assets/" 开头就 `removePrefix("assets/")` 剥一层 → 正确映射 `assets/main.js` / chunk / 字体. PWA 网页版 (pages.dev 根路径单层引用) 不受影响.
- **增强诊断**: onReceivedError 第一次失败立刻 Toast, 不再依赖下次启动 (232 没这个)
- **为何 232 装了不弹 Toast**: 用户装的是对的含诊断的 232-native 包, 但 Toast 要么被 splash 盖住/没注意, 要么没等到 30s 就杀进程; 232 只有 onPageFinished 3s 检查 (可能弹出被忽略), 没有即时 error Toast
- bump 1.10.232 → 1.10.233, commit 092c878 + push → CI 跑 233 native APK (应该能真进了)
